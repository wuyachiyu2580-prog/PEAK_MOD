# StateKeeper 可解释归因引擎

> 当前版本已由 `REPORT_REBUILD_2026-09-08.md` 更新为analysisVersion5、62项测试。下面是version4机制归档；新有效区间/时钟/生命周期合同优先。喂食明确消耗计消费者，来源推断必须标注，不把持有人计成施救者。

更新时间：2026-09-08。本轮已完成基础归因流水的代码接入与离线验收，不需要重新录制整局。此文更新 `RESEARCH_ASSISTANCE_2026-09-08.md` 中“归因流程尚未实现”的历史状态。

## 实现范围

- 原始数据 schema 仍为3，没有增加本轮高频采集字段；派生缓存 analysisVersion=4，版本3缓存自动重建。
- `RunAnalysisEngine` 负责分块时序、库存GUID、曲线和原始事件；新增 `ItemAttributionEngine` 处理候选与结果归因；`RecordedItemRules` 只解释记录中的定义，不访问Unity对象、不执行Action。
- 消耗、被喂、施放完成、有效资源减少、Used变为真、库存消失分别进入证据流水。纯消失始终是弱证据；烹饪次数增加不当成使用。
- 同GUID同次操作的消耗/施放/资源差分合并为 attributionGroupId，保留各原始观察，不把多个证据算成多个使用。不同物品或重复同类事件不因此合并。
- GUID转交支持先移除后出现、先出现后延迟移除两种快照到达顺序；两秒窗口外持续重叠仍是不明确的实例冲突。移除后换槽/转交会撤销弱使用解释。

## 匹配口径

1. 先生成普通体力、额外体力、普通状态、可选石化、Affliction出现/消失、昏迷恢复的变化。
2. 原始变化暂存两秒，使稍后到达的消耗/库存证据也能公平参与竞争。即时效果允许事件前0.75秒至后1.5秒的观察误差；这些是匹配参数，不是网络延迟实测承诺。
3. 按记录的Action触发器、状态通道、方向、数量/容量/预算、时延、持续区间和受益者筛选。没有明确目标时，结合候选来源与玩家位置；普通互喂使用游戏默认2世界单位距离加1单位身体/相机容差，不能误用米制距离。
4. 范围效果支持一对多。Action_ApplyMassAffliction的物品中心未采集时，记录候选但保持不明确；InfiniteStamAmulet明确以角色Center为中心，可使用记录位置。边界容差单列不确定原因。
5. 同通道多个候选、未知物品竞争、自然恢复、多人同时恢复、营地/山段附近恢复、角色变形、死亡/复活、传送式位置跳变、缺帧和时钟重置均阻止不可靠升级。
6. 同物品多个同通道Action可累加；单次剂量有累计预算，不能逐帧重复使用全部额度。HealAll按游戏状态优先顺序分配预算；持续治疗核对优先级和速率。小于理论量的净变化保留，因为容量截断和同期消耗可能抵消效果。
7. 源码中明确的治疗前后差记录可形成Certain证据；规则相符且没有竞争解释为Likely；其余为Ambiguous。物品消耗事实为Certain不代表其效果归因为Certain。

## 机制覆盖

- Action_RestoreHunger、GiveExtraStamina、ModifyStatus、ClearAllStatus、ApplyInfiniteStamina。
- ApplyAffliction与嵌套/额外Affliction：加成状态、AdjustStatus、AddBonusStamina、HealAll预算、PoisonOverTime、DrowsyOverTime、ColdOverTime等。
- 延迟毒按delay与持续时间匹配，不再使用统一四秒窗口。
- 随机蘑菇使用事件发生前已记录的随机上下文；未来捕获的配置不回填过去。三秒延迟、即时状态和额外体力分别匹配。未采集随机上下文时保留未知。
- FasterBoi和InfiniteStamina到期副作用以观察到的Affliction消失锚定，避免假设到期一定发生在标称秒数（加时/叠加可能改变时间）。
- HealingAmulet、InfiniteStamAmulet、DoubleJumpAmulet按可用槽位与PowerEnabled建立持续区间，关闭/移出/观察中断后停止匹配。普通跳跃事件不能证明双跳石化代价，相关解释仍标参数/条件不完整。
- 默认烹饪的饥饿、额外体力、烧焦毒性和损坏状态；未解释的自定义烹饪规则明确降级，不能把未应用的原始prefab量当成最终理论量。
- 旧parameterSummary只解析格式明确的标量；不补造旧格式没有记录的枚举或嵌套对象。结构化字段优先。
- 未知MOD Action保留类型、参数和观察结果，不通过名称相似度猜测作用；这种输出是算法正常结果，不是阻塞整局分析。

## 救援与展示

- possibleHelp/possibleRescue属于派生提示，不能累加进直接救援次数。可能救援还要求同一受益者的可信治疗变化与随后脱离昏迷，单纯加体力/给增益不算救人。
- 原有PlayerFriendHealed、PlayerLifeSaved、PlayerRescuePulled、PlayerRevivedObserved分别保留口径，未知施救者不给主机或最近玩家记功。
- 面板物品行分别显示事实置信度与效果归因；置信度筛选改为归因等级。证据页展示逐项结果、规则来源、数量、时延、竞争候选的物品名/玩家与不确定原因。
- 一个物品有一项Likely效果，不表示其所有效果都已确认；逐项归因保留独立等级。GUID仍只作实例诊断。
- 独立状态变化保存在AnalysisResult.effects，未匹配物品的变化也保留，不要求每个变化都有一个“原因”。普通体力的未关联高频波动仍由曲线保存，避免重复制造大量物品记录。

## 性能与存储

- 不增加5Hz/2Hz频率、Photon RPC、地面扫描或采集线程工作。
- 原始匹配窗口仅保留短时帧/变化；长期候选保留规则和聚合证据，结束后释放候选。连续结果按同方向/连续区间合并，单段最长十秒，保留累计净变化。
- 同时活跃候选设1024个保护上限；触发后报告质量警告并降级，不能因丢失竞争候选而输出虚假的唯一归因。
- 本轮测试六局纯数据读取/聚合约25秒（包含测试运行环境开销），不是游戏主线程性能测量。Unity实机帧时间和UI实际观感未在本轮验证。

## 验证结果

40项测试通过，0跳过：原有存储/救援测试、新增25项归因测试、旧缓存重建测试及六局C#只读回放。

- 资源减少互喂、同次多证据合并、竞争物品、未知MOD竞争、多受益者冲突。
- 单纯消失、两种方向的转交时序、长期GUID冲突不记为确定使用。
- 自然恢复、负时差、延迟毒、蘑菇上下文、持续护符关闭边界、角色中心范围效果。
- 治疗优先预算、跨帧累计预算、默认烹饪、实际到期副作用、直接治疗无后续采样也保留直接证据。
- 死亡/缺帧/传送断点、取消、旧缓存自动失效、可能救援不计直接次数。
- 重复直接治疗先去重再生成归因证据；后到的烹饪信息重建理论规则时保留直接治疗规则，两项均有回归测试。
