## 一、共享发布：按房间会话去重

主要位置：主插件 UpdateRoomState:1719、PublishShareStateIfNeeded:1785、OnMasterClientSwitched:1972；行号对应本轮未修改源码。

- 用当前在线 Room 对象引用记录会话，名字仅用于显示/日志。离房、切入离线房、Room 实例变化时清发布缓存、接收快照和旧房 session overlay；同名新房也不能复用旧缓存。
- 每次房主变更使本地发布缓存失效；本机成为房主后发布当前本地预设，不能复用旧房主的发布身份。
- 去重键含 Room 会话、发布者 actor、ShareMode、protocol、payload；保留 WIT.Hash 算法与字段，不能用 hash 单独代替完整内容比较。
- 只有在线、当前房主、Room 和 LocalPlayer/有效 actor 都就绪时提交；临时无法发送时保留待发布，不把 -1 actor 缓存成成功。
- SetCustomProperties 返回 false：保持 dirty、不记录成功快照；保留 0.25 秒发送节流。需区分紧急失效与失败重试，避免反复 MarkDirty 绕过限流。
- 返回 true：记录“已提交快照”并清本次 dirty。**这是接受发送，不是服务器回显已经完成**；不能因本地房间属性还没回显而每帧重复广播。

本地证据：3.1.0/PhotonRealtime/Photon.Realtime/Room.cs:214–232 在线返回底层发送 bool；LoadBalancingClient.cs:1076–1093 只在关闭 BroadcastPropertiesChangeToAll 且无 CAS 时立即写本地缓存并回调。Assembly-CSharp/Peak.Network/NetworkingUtilities.cs:79–86 的游戏房间选项无需改动。

首批不新增 RPC、CAS、定时心跳或协议版本，保留协议 2 和五个 WIT 属性。检查 bool 不等于实现服务器确认；服务器拒绝/断线/延迟回显留在真实网络验收。只加 roomName 或只在换场景时清缓存都不够。

## 二、目录就绪：自动补发，避免依赖房主打开菜单

位置：TryLoadCatalog:1056、SaveLocalPresets:1343、ThingTypes.cs/ThingCatalog.Load:401。

1. 房主处于 PublishedPresets、目录未就绪时，在房间维护中每 0.5 秒尝试加载；成功后停止。无需用户先开菜单或按扫描。
2. 区分“有场景/箱子条目”与“有真实可用物品定义”。完全空物品库不能完成目录缓存、删除旧选择 token 或写迁移完成标记。至少有真实可用 prefab 才提交该目录。
3. 提交顺序保持：构建索引 → 身份/放置物迁移 → 解析内置目标 → 保存 → 有效选择缓存失效 → 标记共享 dirty。
4. 在成功提交目录的低频入口标 dirty 即可；发布快照比较负责压掉内容未变的网络发送，不需要每次扫描额外序列化。长期可把预设内容变更通知统一集中，但要允许初始化/离线时只标记不发送。

首次可保留现有启动发布，确保自定义预设/已有 ID 立即可用；目录准备好后补发最新内容。彻底隐藏启动时短暂空内置预设需要延迟首发，是可选行为，不是必要修复。

空库保护只解决完全空库，**不能保证其他 MOD 分批加载已完成**。不要写死必须有 182 个物品，也不能要求晚安莓必须存在。热替换/分批注入另需明确的目录版本或失效信号。

## 三、客机接收：分开共享缓存、标注刷新与本地编辑

位置：OnRoomPropertiesUpdate:1959、ApplySharedStateFromRoomProperties:1821、HasUsableSessionPresets:1413。

1. 无 WIT mode/protocol/actor/payload/hash 变更的回调直接返回。
2. 有关事件从完整 CurrentRoom.CustomProperties 读快照，不能把 delta 当成完整状态。删除/null/类型错误仍进入既有回退。
3. 接收缓存键含 Room、当前 Master actor、mode/protocol/actor/payload 的类型和值；相同快照不重复解码。保留 WIT.Hash 兼容，单独 hash 变化不重算目标。
4. 解析返回“有效共享视图是否改变”，包括有效性、来源、目标/名称、当前选择，不仅是列表数量。
5. 受限客机只在真实变化后刷新标注及只读列表，保留扫描截止；已停止/过期扫描不因同步而复活。
6. 自由客机仍更新共享缓存供以后切回，但不替换本地选择、不重新 Open 编辑窗口、不打断重命名。

保留同房换房主时三秒宽限：新 actor/protocol/payload 合法后立即接管；过期即使没有回调也由主循环清旧 overlay。新 Room 立即清旧数据，不继承宽限。接收去重和过期清理分开，不能因为快照未变就跳过时钟检查；切换客机限制也必须单独刷新有效来源。

## 四、扫描计时：明确续时的入口

位置：RefreshEffectivePresetState:1422、Update:257、CycleLocalScanMode:1653、AdjustLocalDisplayDuration:1661。

将“刷新有效选择/标签”和“重设截止时间”拆开。正式实现用明确方法或枚举；原型第二个 restartTimer 参数仅用于验证，不建议正式调用依赖含糊默认值。

| 事件 | 已有扫描如何处理 |
| --- | --- |
| 用户按扫描键 | 保留原行为，常驻或从现在开始完整定时周期 |
| 主动切本地/共享预设、应用选择、创建/删除、改位置范围 | 保留这些显式操作现有的重新计时行为 |
| 自动同步、换房/房主、宽限到期、目录解析、周期刷新 | 更新内容但保留截止，不续时、不启动已停止扫描 |
| 任一界面常驻→定时 | 正在显示时从变更时刻开始新周期；未显示只改配置 |
| 定时→常驻 | 清有限截止，保持当前显示 |
| 调整定时时长 | 正在定时显示时按新时长重新计时，保持自带 UI 语义 |
| 字体、距离、玩家名等显示设置 | 不重设计时 |
| 同值重复配置 | 无续时和重建副作用 |

优先沿用主线程观察配置值：Update 顶部比较模式与实际 clamp 后时长，变化时统一调用 ApplyScanSettingsChanged。ModConfig 与自带 UI 走同一路径；按钮需立即反馈时调用同一函数并更新观察值，下一帧不重复续时。SettingChanged 也可仅标 dirty，不直接操作 Unity UI。

观察必须在窗口提前返回及到期判断之前，覆盖菜单内变更与到期瞬间改常驻。选择缓存与计时配置分开，不能缓存整个 RefreshEffectivePresetState 后漏掉显示设置变化。

## 五、菜单与标签生命周期

- 菜单输入只拦截游戏扫描热键；Enabled、到期、旧标签有效性与投影继续维护。LateUpdate 的光标恢复逻辑保留。定时仍按 unscaledTime 到期，被摘/禁用目标及时撤标。需要降低菜单内新目标发现频率时可单独处理，不能连旧标签失效一起停掉。这是推荐交互，未实机验证。

## 七、优化的安全实施方式

### 先做低风险部分

1. 选择缓存按本地内容、active 集合、共享视图、catalog 修订号失效；覆盖编辑/创建/删除、迁移、限制切换、房主/房间与回退。语言只影响名称摘要，动态物品状态不能因为选择没变而不检查。
2. 距离变化只更新 distance TMP；名称/玩家名变化再测布局。屏幕内外切换、字号/字体改变仍重排。
3. 先记录 desired key，再检查已存在标签，最后才构造委托；若提前 return 漏掉 desired key，Reconcile 会删仍需要的标签。
4. 同背包 slot 换物、同 viewID 换实例、绳锚替换不能盲目复用旧闭包。比较 binding 身份或使用稳定可更新 descriptor。
5. Open 与 RefreshSettings/RefreshRows 分开。滑块即时更新数值和扫描范围，不销毁整个滑块/列表；保存可合并到拖动结束/短防抖，但关闭窗口/退出需落盘。只读共享更新不能打断本地重命名。

### 晚分类重试分两步

不能简单改为“Item != null 就不重试”，其层级仍可能含放置体/绳索或待解析投掷归属。

- 先保留现有重试覆盖与 0.25ms/32 项预算，候选分类无变化就不销毁标签；保留标签时也要保留/更新其闭包引用的 record，不能替换记录却仍抓旧对象。
- 再按 prefab 来源索引、组件存在但未 ready、归属待解析等明确原因缩小重试。未知动态对象保留短暂容错。
- 对已识别绳索的晚锚定等安排定点重新分类，先覆盖超过 2.1 秒才就绪再缩窗口；不改成永久每帧扫所有未知对象。
- 继续保持投掷证据唯一、歧义留空、晚加入可能没归属的边界，不猜放置者。

### 测量后决定

- 段范围按载体共享短 TTL 缓存，包含 scene/segment revision、map scope、目标/位置，销毁/跨段失效。自定义 positionProvider 不能只按 Transform 合并。
- 场景发现保留类型数组分批处理并加预算；FindObjectsByType 本身的全场查询仍存在，不宣称完全消除峰值。
- 对象池只池化 UI 外壳，清委托/目标、重设样式/可见状态并限容量；虚拟列表需兼顾勾选、折叠、搜索、滚动和本地化。两者都先量性能再实施。
