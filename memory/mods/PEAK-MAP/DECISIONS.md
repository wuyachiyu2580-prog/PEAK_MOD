# PEAK-MAP Decisions

更新时间：2026-09-06

## 已确认决策

- STATE KEEPER 数据提交是自愿、匿名、可通过站点配置关闭的后续功能；当前不改网站源码。
- 新增独立接口 `app/api/statekeeper/submit/route.ts`，不修改或复用现有地图上传接口的业务校验。
- 新增独立的 `statekeeper_submissions` 元数据表，不写入现有 `maps` 表。
- 匿名文件使用随机对象键，例如 `statekeeper-submissions/<random-id>.json.gz`，R2 原始匿名文件默认私有。
- Supabase 只保存提交状态、版本、大小、计数和质量摘要；公开展示以后只允许使用审核后的聚合数据。
- 客户端先脱敏，服务端必须再次脱敏和校验，不能信任客户端提交的匿名结果。
- 玩家名称采用每次提交重新分配的“玩家 A/B/C”等匿名编号；不上传 Photon UserId、ActorNumber、物品 GUID、精确 UTC 时间、原始 detail、本地路径、机器名、配置路径、日志和精确位置。
- 局内相对时间可以保留；距离默认四舍五入到约 5-10 米；坐标默认删除或粗粒度化。这是适度脱敏，不是只改显示名称，也不是上传原始详细数据。
- 提交前必须展示脱敏摘要和用途说明，用户明确同意后才允许网络请求；未同意不上传。
- 必须有独立限流、最大压缩/解压后大小、GZip 魔数、JSON schema、深度/数组/字符串长度和异常清理保护。
- 网站应通过环境变量或 `site_config` 关闭提交入口；匿名提交最好配一次性删除令牌或管理员删除能力。

## 禁止回退

- 不把 STATE KEEPER 数据直接写入地图 `maps` 表。
- 不把匿名提交文件挂到公开 `/api/r2/*` 代理，除非以后明确决定公开并重新审核隐私风险。
- 不在公开统计中使用可还原玩家身份的字段或精确轨迹。
- 不记录包含原始数据的安全日志；短期 IP 安全日志也不得并入分析数据。
- 不把“模糊化名称”误当成完整匿名化；跨局追踪所需的固定玩家标识必须删除，每次提交的匿名编号必须重新生成。
